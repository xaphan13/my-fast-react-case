# FastAPI + React: цикл гайдов по современной веб-разработке

> Практический цикл «как делать и почему именно так» на примере живого проекта
> `my-fastapi-one` (FastAPI 0.111+ / Python 3.12 / SQLAlchemy 2.0 async — бэкенд;
> React 18 + TypeScript + Vite + Tailwind CSS v4 — фронтенд).
> Все примеры кода — реальные куски из этого репозитория, не выдуманные.

## Для кого

Вы умеете писать на Python и немного на JS/TS, но связка «бэкенд + SPA» кажется
набором магических слов: Vite, CORS, SPA fallback, DI, миграции, cookie-сессии.
Цикл раскладывает всё по полочкам: **что делать → почему так → как выглядит код →
какие есть альтернативы**.

## Главные идеи цикла (TL;DR)

- **React живёт в браузере, FastAPI — на сервере.** Единственное, что их связывает,
  — контракт JSON API. Всё остальное — детали сборки и деплоя.
- **«Запущенный фронтенд» — условие разработки, а не работы сайта.** В проде
  FastAPI раздаёт собранную статику и сайт работает одним процессом.
- **DI (`Depends`) — главный паттерн FastAPI**: сессия БД, авторизация, параметры —
  всё через него. Один переиспользуемый алиас `CurrentSession` заменяет сотни строк.
- **Pydantic-схемы — это контракт**: валидация входа, сериализация выхода и
  автодокументация OpenAPI из одного описания типов.
- **Типы на обоих концах** (Python dataclass'ы/pydantic ↔ TypeScript-интерфейсы)
  убирают целый класс багов «а что приходит в этом JSON?».
- **Альтернативы существуют не зря**: SSR (Next.js) — для SEO, Jinja2 + htmx — для
  простоты, раздельные домены — для команд и CDN. Выбор зависит от задачи, а не моды.
